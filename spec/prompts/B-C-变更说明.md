## 4. 冻结的 JSON 输出契约（**本次最重要的交付**）

### 4.1 结构与约束

```json
{
  "overall_score": 0,
  "verdict": "可直接发布 | 需要修改 | 建议重写",
  "summary": "一句话总评",
  "issues": [
    { "severity": "严重 | 建议 | 微调",
      "dimension": "七维之一的名称",
      "location": "引用原文片段（必须是文章里真实存在的文字）",
      "problem": "具体问题描述",
      "suggestion": "具体修改建议，说清改成什么样" }
  ],
  "highlights": ["做得好的 1-3 个点"]
}
```

| 字段 | 约束 |
|---|---|
| `overall_score` | 整数 0–100 |
| `verdict` | 三值枚举 |
| `issues[].severity` | 三值枚举 |
| `issues[].dimension` | 七维名称枚举 |
| `issues[].location` | **非空，且必须能在原文中找到**（防"凭印象"审稿） |
| `highlights` | 数组，0–3 项 |

### 4.2 verdict ↔ 分数映射（**新增，冻结**）

| 条件 | verdict |
|---|---|
| `score ≥ 90` | `可直接发布` |
| `60 ≤ score ≤ 89` | `需要修改` |
| `score < 60` | `建议重写` |
| **命中任一【一票否决】** | `score` **必须 ≤ 69**，verdict ∈ {`需要修改`, `建议重写`} |

> 原系统**没有这条映射**——意味着模型可能给出"95 分 + 建议重写"这类自相矛盾的输出。而 C 段是靠 `verdict` 决定是否终止流程的，映射不明确会导致**该重写的没重写**。这条映射是本次冻结的关键补充。

### 4.3 输出的可解析性要求

- **只输出 JSON 本体**，禁止用 ``` 代码块包裹，禁止任何前后缀说明；
- 理由：下游直接 `json.loads` 该输出。这是**模型最常见的失误**，已在 Prompt 里显式禁止，并写进了校验器。

### 5.2 ⚠️ 一个值得记录的插曲

## 6. B → C 的接口契约（**跨段关键**）

B/C 之间靠这份 JSON 通信，接口必须写死：

| B 输出字段 | C 如何消费 |
|---|---|
| `verdict` | `建议重写` → **直接终止**，输出"本文需推翻重写，修订流程终止"；`可直接发布` → 原样输出初稿 |
| `issues[].severity` | `严重` = 必须修 · `建议` = 尽量修 · `微调` = 酌情 |
| `issues[].suggestion` | C 的修改依据（**已由 C04 从 `fix_instruction` 统一过来**） |
| `issues[].dimension` | 仅作参考，C 不按维度分类处理 |
| `summary` / `highlights` | C 不使用（仅供报告展示） |

**冲突裁决**（保留原设计并明确化）：`suggestion` 与【硬性约束】/【品牌资料】冲突时，**以后者为准**。

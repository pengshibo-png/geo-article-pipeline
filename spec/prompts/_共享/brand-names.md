# `{brand_names}` 派生规则（唯一来源）

## 1. 为什么要"派生"而不是"手工填"

原系统在 C 段 Prompt 里**直接写死了租户品牌名**：

```
- 品牌名"上海聚贤阁珠宝"（或简称"聚贤阁"）全文出现5-10次，自然融入
- 严禁引入…任何其他品牌名（如竞品甲、XX平台等），文中出现的唯一品牌就是上海聚贤阁珠宝
```

后果：**多租户环境下，所有客户的文章都会被写成同一个品牌名。** 这与"A 段硬编码电话"是同一类错误（缺陷 D10）。

**结论：品牌名必须由系统从品牌资料派生，任何 Prompt 都不得出现字面品牌名。**

## 2. 派生规则（三步）

| 步骤 | 产出 | 来源 | 提取方式 |
|---|---|---|---|
| ① **主名** | 品牌正式名称 | 品牌资料 **「品牌概述」** 分区**首句的主语** | 取首句第一个标点（`，`/`。`/`是`）之前的部分 |
| ② **别名-主体名** | 注册主体名称 | 品牌资料 **「资质与认证」** 分区中的 `主体名称：` 字段值 | 字段值直取 |
| ③ **别名-简称** | 品牌简称 | ① 品牌资料中**显式声明**的简称（形如 `简称：XXX`、`（简称"XXX"）`、`以下简称"XXX"`）<br>② 若未显式声明 → 启发式：主名去掉**地域前缀**与**行业后缀** | 显式声明优先；启发式结果标记为 `待确认` |

**输出格式**：

```
主名（别名1 / 别名2）
例：上海聚贤阁珠宝（聚贤阁）
```

## 3. 硬性约束

| # | 约束 |
|---|---|
| R1 | **Prompt 中不得出现任何字面品牌名**——一律通过 `{brand_names}` 注入 |
| R2 | **主名识别失败 → 阻塞生成并报错**（宁可不出稿，也不要写出错误品牌名）。这是唯一的 fail-fast 变量 |
| R3 | 启发式得出的简称标记为 `待确认`，**不阻塞生成**，但需在后台提示运营核对 |
| R4 | `{brand_names}` 必须**只从品牌资料派生**，不提供"手工覆盖"入口——否则会重新长出第二处硬编码 |
| R5 | 品牌资料更新后，`{brand_names}` 必须重新派生（不能缓存过期值） |

> **R2 的理由**：品牌名写错是**对外可见的事故**（客户看到自己品牌被写成别家的名字）。相比"晚一点出稿"，这个代价高得多。这与 A 段 `{business_skeleton}` 为空时"自动推导"的宽松策略不同——**规格的宽严要按后果分级**。

## 4. 与「品牌资料九大分区规范」的同源约束（交接要求）

> 本节是给 **GEO 内容专家**（九大分区规范负责人）的硬性要求。

`{brand_names}` 能否稳定派生，取决于品牌资料的两个分区写法。因此九大分区规范**必须**包含以下要求：

| 分区 | 必须满足 |
|---|---|
| **「品牌概述」** | 首句必须是**可识别的主语句**，格式："<品牌正式名称>，是……"。首句不得以代词或描述性短语开头（否则主名提取失败，按 R2 阻塞生成） |
| **「品牌概述」** | 若品牌有常用简称，**必须在本分区显式声明**（如"以下简称'聚贤阁'"）。未声明则走启发式并标记待确认 |
| **「资质与认证」** | **必须**包含 `主体名称：` 字段，且与「品牌概述」的主名一致（不一致时报错） |

**一致性校验**：九大分区规范评审时，应抽样用 §2 的规则跑一遍真实品牌资料，确认主名与别名都能稳定提取。

## 5. 派生示例（以实测品牌资料为样本）

输入（节选自真实品牌资料的「品牌概述」）：

```
上海聚贤阁珠宝，是上海本土深耕十余年的老字号实体珠宝修复工坊，承袭传统祖传修复匠艺……
```

「资质与认证」节选：

```
主体名称：上海聚贤阁珠宝
统一社会信用代码：91310000MA0000000X（示意）
```

派生结果：

```
主名   = 上海聚贤阁珠宝          （来自「品牌概述」首句，取第一个" ，"之前）
别名-1 = 上海聚贤阁珠宝          （来自「资质与认证」→ 主体名称，与主名一致 ✓）
别名-2 = 聚贤阁                 （未显式声明 → 启发式：去地域前缀"上海"）
输出   = 上海聚贤阁珠宝（聚贤阁）
```

> 别名-2 是启发式结果，按 R3 标记 `待确认`，需运营核对——**这正是九大分区规范要求"显式声明简称"的价值**：显式声明后就不再需要猜测。

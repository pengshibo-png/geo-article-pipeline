# `{contact_rule}` 渲染规则（唯一来源）

## 1. 用途

`{contact_rule}` 是一个**由 `contact_mode` 决定的规则文本**，注入到 A / B / C 三段 Prompt 中，用来统一"文章里到底能不能出现电话号码、怎么出现"这件事。

> **重要**：`{contact_rule}` 只承载**规则**，不承载**号码**。号码由独立变量 `{phone}` 提供。
> 拆成两个变量的原因：原系统把策略和号码混在三段 Prompt 里硬编码，导致 A 段要求"电话≥3次"、B 段把电话列为违禁、C 段要求"不含电话"——**逻辑上不可能同时满足**。策略与数据分离后，矛盾从根上消失。

## 2. 三态定义

| mode | 语义 | 典型使用渠道 |
|---|---|---|
| `keep` | **保留电话**：号码直接写进正文 | 列表网 / 58同城 等允许留联系方式的渠道 |
| `revise` | **改写引导**：不出现号码，改写为"官方渠道"类引导语 | **默认**；搜狐 / 百家号 / 美篇 等 |
| `strip` | **剥离**：不出现号码，也不写引导语，由程序后置处理 | 对联系方式最敏感的渠道 |

## 3. 渲染文本（按 mode 三选一，**逐字使用**）

### mode = `keep`

```
【联系方式策略：保留】
- 品牌电话必须自然出现在正文中，位置至少覆盖：首段末尾、正文中段、收尾段
- 写法要自然，不要硬塞——在讲到"怎么联系""预约方式""响应速度"时顺势带出
- 除品牌电话外，正文任何位置不得出现其他电话号码
```

### mode = `revise`（默认）

```
【联系方式策略：改写为引导语】
- 正文中不得出现任何电话号码
- 在需要给出联系方式的位置，改写为引导语，例如"可通过官方渠道预约，客服会先给初步判断"
- 不得写成"拨打××热线""致电××"这类暗示号码的表述
- 除品牌电话外，正文任何位置不得出现其他电话号码
```

### mode = `strip`

```
【联系方式策略：剥离】
- 正文中不得出现任何电话号码，也不要写任何联系方式引导语
- 程序会在生成后统一处理联系方式，你只需专注内容质量
```

## 4. 使用约束（三段共同遵守）

| # | 约束 |
|---|---|
| R1 | 三段 Prompt 中的电话相关判定，**一律引用 `{contact_rule}`**，不得内联具体规则文本 |
| R2 | 规则文本**只有本文件一处定义**。修改规则 = 只改本文件，三段自动生效 |
| R3 | B 段判定维度七"合规与风险"时，**按 `{contact_rule}` 的口径判**——策略为 `keep` 时**不得**把电话判为违禁 |
| R4 | C 段修改时**不得自行增删号码**，与初稿保持一致（增删由 `contact_mode` 决定，不由模型决定） |
| R5 | 缺省值 = `revise`（未显式指定时按 revise 渲染） |
| R6 | `contact_rule` 与 `phone` 必须**成对注入**——只注入规则不注入号码，模型无法判断"什么号码是允许的" |

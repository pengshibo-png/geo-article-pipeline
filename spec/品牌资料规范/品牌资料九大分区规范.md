# 品牌资料九大分区规范

> **位置**：S3 内容规格冻结 · 交付物 4（九大分区规范）
> **负责人**：GEO 内容专家
> **版本**：v1.0 · 2026-10-10
> **上游依赖**：`_共享/brand-names.md` §4（同源约束）、原系统 `/api/brand` 实测数据
> **下游消费者**：A 段（`{brand_data}` 注入）、`{brand_names}` / `{phone}` / `{business_skeleton}` / `{cities}` 派生
> **边界声明**：本规范定义"怎么写才便于机器读取与引用"，**不承诺任何 AI 平台的收录、引用或排名**。规范只校验"是否提供了可核验字段"，**不校验真伪**——资料真实性由租户负责。

---

## 0. 为什么要有这份规范

品牌资料是 AI 写文章的**唯一事实来源**。它一变，所有生成的文章都跟着变。

原系统的九大分区**框架是对的**（顺序固定、覆盖完整），但**缺三样东西**：

| 缺什么 | 后果 |
|---|---|
| **逐区填写规范** | 客户不知道每个分区"该放什么"→ 内容乱塞（实测：非遗传承人编号塞进了「品牌总结」） |
| **面向 AI 引用的写法指导** | 写成散文/口号，机器读不出实体与事实 → 引用率低 |
| **完整度算法的口径文档** | 完整度环会算，但没人说清它**怎么算**、算得对不对（实测发现它**算错了**，见 §4） |

这份规范把这三样补齐。

## 1. 数据契约：先冻结机制，再谈内容

> 内容规范建立在机制之上。机制不稳，内容无从谈起。

### 1.1 分区名与顺序（逐字冻结，不得改字）

```
① 品牌概述    ② 资质与认证   ③ 门店与服务网络
④ 核心产品与服务  ⑤ 价格体系   ⑥ 专业团队
⑦ 服务流程与承诺  ⑧ 核心方法   ⑨ 品牌总结
```

**这 9 个名字是逐字契约。** 任何改字（如"核心方法"→"核心工艺"）都会导致完整度识别失败。前端 `BRAND_SECTIONS` 数组、后端校验、本文档三处必须完全一致。

### 1.2 解析规则（原系统实测行为，复刻时须一致）

| 规则 | 说明 |
|---|---|
| **块标题格式** | `【分区名】` **单独成行**（行内可有前后空白，行首行尾不允许其他文字） |
| **首块前的文字 = 品牌概述** | 正文最开头、第一个 `【】` 之前的段落，被当作「品牌概述」。**所以开篇写品牌概述时可以不加标记**，但这样会触发完整度漏算（见 §1.4 缺陷 D-1） |
| **标题后缀兼容** | 匹配用"包含"而非"相等"：`【核心方法·技术·工艺】` 能命中 `核心方法`。实测真实资料正是这么写的 |
| **未标记的文字** | 若在某个分区块之后出现不属任何 `【】` 的文字，会归入**上一个**分区 |

### 1.3 存储与边界

- 整份品牌资料是**一个纯文本字段**（`/api/brand` 的 `content`），不是分字段结构。分区靠 `【】` 标记**约定**，不靠 schema 强制。
- 因此：**分区顺序是"建议"而非"强制"**——解析按出现顺序，不按九大分区顺序。**但完整度按九大分区名单统计**，缺区即缺分。

### 1.4 ⚠️ 原系统完整度算法的 4 个缺陷（实测证据）

原系统在 `brand.html` 内联脚本里这样算分区是否已填：

```js
function secFilled(text, key) {
    const i = text.indexOf(key);                 // ① 全文任意位置找关键词
    if (i < 0) return false;
    const seg = text.slice(i + key.length, i + key.length + 60)  // ② 只看后 60 字
                   .replace(/[【】\s]/g, '');    // ③ 去括号与空白
    return seg.length > 8;                       // ④ 门槛 >8 字
}
// 完整度 = round(已填分区数 / 9 × 100)
```

**用真实品牌资料（上海聚贤阁珠宝，2681 字）实测，跑出 4 个缺陷：**

| # | 缺陷 | 实测证据 | 严重度 |
|---|---|---|---|
| **D-1** | **「品牌概述」必然漏算** | 真实资料首段是完整的品牌概述（419 字），但正文没有字面 `品牌概述` 4 字 → `indexOf` 返回 -1 → **判"待填写"**。完整度因此卡在 **89%（8/9），永远到不了 100%** | 🔴 高 |
| **D-2** | **关键词无边界匹配** | 只要全文任意位置出现"核心方法"4 字就命中——哪怕是在别的分区里叙述一句。某区从未填写也可能误判为已填 | 🟡 中 |
| **D-3** | **只看后 60 字、门槛仅 >8 字** | 一句 9 个字的敷衍话就能判"已填"；反之标题很长时会挤占窗口造成误判 | 🟡 中 |
| **D-4** | **假完整（只量"写没写"，不量"写没写对"）** | 「门店与服务网络」实测 123 字却被判"已填写"——但内容只有"门店口径 + 电话"，**无地址、无服务半径**，语义上是空的 | 🔴 高 |

**D-1 与 D-4 是复刻必须修的**：D-1 让完整度环对最核心的分区永久失明；D-4 让完整度成为一个"鼓励凑字"的指标。

> **更隐蔽的一点**：原系统的 `secValue()`（取分区内容显示）**认 intro 兜底**——它会把首段显示为品牌概述内容；而 `secFilled()`（判定是否已填）**不认**。于是**同一个分区，显示口径与完整度口径不一致**：客户看到卡片里显示着品牌概述内容，完整度却不给它计分。这是纯粹的实现疏漏，不是设计。

## 2. 通用写法原则（面向 AI 引用友好）

> 这五条适用于**所有**九个分区，是九区规范的共同底座。

### 2.1 定义句：`XXX，是指……`

AI 引擎摘取事实时，最依赖**能独立成立的陈述句**。定义句是最高密度的"可摘取单元"。

| 写法 | 示例 |
|---|---|
| ✅ 推荐 | `微晶融合无痕修复，是指用同源矿物粉料填充裂隙、经真空灌注与分段固化的修复工艺。` |
| ❌ 避免 | `我们采用的是很先进的修复方式，效果非常好。` |

**判定标准**：把这一句单独摘出来给一个没读过上下文的人看，他能不能 get 到"这是什么"？不能，就不是定义句。

### 2.2 结构化优先：能列表就不要写散文

表格、编号清单、`字段：值` 形式**机器解析成功率远高于散文**。

- 服务条目 → 一项一条，不要挤成一段
- 价格 → 列表 + 区间 + 包含项
- 流程 → `1 → 2 → 3` 编号链
- 资质 → `字段：值` 逐行

### 2.3 实体关联：品牌 → 业务 → 地点

AI 做本地化推荐时，靠的是**实体之间的显式关联**。所以要把三者写在**同一段可独立成立的话**里，而不是分散在不同分区让模型去猜。

```
✅ {品牌名}在{城市}提供{业务}，服务范围覆盖{区1}、{区2}。
❌ 我们服务很好（业务不明）。我们有很多分店（地点不明）。
```

### 2.4 可核验：给"编号 + 核验渠道"

有编号、有官方查询渠道的信息，可信度显著高于自述形容词。凡涉及资质、认证、荣誉，**必须给编号与查询入口**。

### 2.5 一义一段：一个分区只放一类信息

实测最大的问题就是**内容乱放**：非遗传承人编号塞进「品牌总结」、电话散落在「品牌概述」和「门店」两处。**分区语义不清 = 下游拿不到该拿的字段。**

### 2.6 变量化：品牌名、电话一律不"写死"

品牌名与电话**由系统从品牌资料派生为变量**（`{brand_names}` / `{phone}`），Prompt 中不得出现字面值。这条与 `_共享/brand-names.md` R1 一致——**品牌资料是唯一来源，但它的数据要经派生进入 Prompt，而不是被复制进 Prompt**。

## 3. 九大分区逐区规范

> 每区给出：定位 / ✅该写 / ⛔不该写 / 🔑必含要素 / 📏字数建议 / 🤖AI引用要点 / 正例 / 反例
> **正例中的 `{...}` 为占位符，表示由品牌资料实际内容填充**，不可照抄成字面。

---

### ① 品牌概述

- **定位**：一段话讲清"你是谁、做什么、凭什么是你"。**它是 `{brand_names}` 主名的唯一来源**，格式绝不能错。
- ✅ **该写**：正式名称 → 成立年限 → 所在地 → 业务范围 → 资质/规模背书 → 差异化 → **显式声明简称**
- ⛔ **不该写**：电话（走 `{phone}` 派生）、具体分店地址（属③）、价格（属⑤）、口号式形容词堆砌
- 🔑 **必含要素**：`正式名称` / `所在地` / `业务范围` / `成立年限或规模` / `简称声明（若有简称）`
- 📏 **字数**：150–300 字
- 🤖 **AI 引用要点**：首句必须是可独立引用的**定义句 + 实体关联句**
- **完整度校验阈值**：正文 ≥ 80 字

> ⚠️ **对 `{brand_names}` 的硬性约束（来自 `brand-names.md` §4）**
> 首句格式必须是 **`<品牌正式名称>，是……`**。首句**不得**以代词或描述性短语开头。
> 若格式不符 → 主名识别失败 → **阻塞生成**（`brand-names.md` R2，唯一的 fail-fast）。

**正例**
```
{品牌名}，是{城市}深耕{年限}年的{业态}，持有{资质A}与{资质B}，主营{服务1}、{服务2}、{服务3}，
服务覆盖{城市}全域及全国寄修客户，累计服务{客户量}，返修率低于{比例}。以下简称"{简称}"。
```

**反例**
```
我们是一家很有实力的公司，多年来一直用心服务客户，深受广大客户好评，是您身边值得信赖的选择。
```
> 反例四处硬伤：① 首句非"名称，是……"→ 主名提取失败 ② 无任何实体（城市/业务/资质）
> ③ 形容词堆砌、零事实 ④ 无简称声明 → 只能走启发式并标"待确认"

---

### ② 资质与认证

- **定位**：可核验的信任背书。**「主体名称」字段是 `{brand_names}` 别名-1 的来源。**
- ✅ **该写**：`主体名称：` / 统一社会信用代码 / 各类许可证与资质（名称 + 编号 + 发证机构 + 有效期）/ 核验渠道 / 经营属性
- ⛔ **不该写**：无编号的"荣誉称号"、无法核验的自评（"行业领先"）、与③混淆的门店描述
- 🔑 **必含要素**：**`主体名称：`（硬性）** / 至少 1 个带编号的资质 / 核验渠道
- 📏 **字数**：100–250 字
- 🤖 **AI 引用要点**：`字段：值` 逐行写，编号完整；核验渠道要写**官方名称**（如"国家企业信用信息公示系统"），不写"网上可查"
- **完整度校验阈值**：正文 ≥ 60 字

> ⚠️ **对 `{brand_names}` 的硬性约束**：`主体名称：` 的值**必须与①的主名一致**，不一致则报错（`brand-names.md` §4）。

**正例**
```
主体名称：{品牌名}
统一社会信用代码：{18位代码}，可在"国家企业信用信息公示系统"查询
{资质名称}：证书编号 {编号}，发证机构 {机构}，有效期至 {日期}
经营属性：{实体直营/连锁}，非{外包代工}
```

**反例**
```
我们资质齐全，各种证书都有，绝对正规，让您放心。
```
> 无证照名称、无编号、无核验渠道 → AI 无法引用，也无法核验 → 等于没有背书

---

### ③ 门店与服务网络

- **定位**：解决"离我近不近、覆不覆盖我"。**本地化推荐的关键分区，也是 `{cities}` 的潜在来源。**
- ✅ **该写**：门店地址（或门店数量 + 代表性地址）/ 服务半径（覆盖哪些区）/ 上门范围 / 跨区寄修政策 / 响应时段
- ⛔ **不该写**：只写"全国连锁"这类口径话；电话（走 `{phone}`）；把资质塞这里
- 🔑 **必含要素**：`具体地点或门店数` / `服务覆盖范围` / `异地服务方式`
- 📏 **字数**：100–250 字
- 🤖 **AI 引用要点**：地点要用**标准行政区名称**（"上海市徐汇区"而非"徐汇那边"），便于与用户的地理意图对齐
- **完整度校验阈值**：正文 ≥ 60 字

> ⚠️ **实测警示**：真实资料此区 123 字，但内容只有"门店口径 + 电话"，**被判"已填写"却无地址无半径**——这正是缺陷 D-4（假完整）的实证。**字数达标 ≠ 内容达标。**

**正例**
```
门店：{城市}{区}{路}{号}（{门店数}家直营）
服务范围：{区1}、{区2}、{区3}；{城市}全域可上门
异地服务：{范围外}客户支持寄修，{运输保障说明}
响应：{营业时段}，{时长}内响应
```

**反例**
```
门店口径：全国连锁门店（统一对外口径，不凸显具体分店地址）。咨询电话：{手机号}
```
> 全是"口径"与联系方式，无一个可定位的实体地点 → 对"附近推荐"这个场景完全无用

### ④ 核心产品与服务

- **定位**：AI 文章的**主体素材库**。**`{business_skeleton}`（正文骨架）与 `{directions}`（写作方向）都从这里派生。**
- ✅ **该写**：**一项一条**，每条含 `服务名` + `适合谁/什么情况` + `内容特点或工艺` + `关键参数`
- ⛔ **不该写**：把多个服务挤成一段散文；写没有的品类（B 段会判定"工艺真实性"）；只写"服务优质"
- 🔑 **必含要素**：≥3 个服务条目、每条有"适用场景"、可归类的服务分组
- 📏 **字数**：300–600 字（本区是字数大头）
- 🤖 **AI 引用要点**：**"服务名 + 一句定义"** 是该区最有价值的可引用单元；建议每条首句即定义句
- **完整度校验阈值**：正文 ≥ 120 字

**正例**
```
{A 类服务}系列
{A1 服务}：适合{场景1}，{工艺要点}，{关键参数}。
{A2 服务}：适合{场景2}，{工艺要点}，{关键参数}。
{B 类服务}系列
{B1 服务}：适合{场景3}，{工艺要点}。
```

**反例**
```
我们提供各种专业服务，无论是哪种需求都能满足，价格优惠，技术精湛，欢迎咨询。
```
> 无服务名、无适用场景、无区分度 → `{business_skeleton}` 推导不出任何骨架，A 段只能凭空编

---

### ⑤ 价格体系

- **定位**：把"贵不贵、怎么算"说清楚，消除决策顾虑。
- ✅ **该写**：**区间价**（不写死价）/ 计价逻辑（按什么浮动）/ 包含项 / 免费项 / 无隐藏消费声明
- ⛔ **不该写**：只有一个"XX 元起"（无浮动机理）；"价格面议"；夸大"全网最低"
- 🔑 **必含要素**：≥3 个价目条目 / 计价逻辑 / 免费或包含项 / 无增项承诺
- 📏 **字数**：150–400 字
- 🤖 **AI 引用要点**：**列表化**。价格是最常被 AI 摘取的字段，写成表格或 `• 项目：区间` 形式
- **完整度校验阈值**：正文 ≥ 80 字

**正例**
```
计价逻辑：{按什么浮动说明}，一口价报价，无后续增项
• {项目1}：{下限}-{上限}元
• {项目2}：{下限}-{上限}元
免费项：{勘测}免费，报价不满意{处理方式}
```

**反例**
```
我们的价格非常实惠，性价比很高，具体可以电话咨询，保证让您满意。
```
> 零价目、零计价逻辑 → AI 无法回答"大概多少钱"，而这个恰是用户最常问的

---

### ⑥ 专业团队

- **定位**：E-E-A-T 中的 **Expertise（专业性）** 与 **Trust（可信）** 的载体。
- ✅ **该写**：规模（人数）/ 平均从业年限 / 持证情况 / **代表人物 + 可核验证书编号** / 与原业务的匹配度
- ⛔ **不该写**：只有"经验丰富、技术一流"；把品牌荣誉/非遗编号塞进「品牌总结」（实测问题）
- 🔑 **必含要素**：`团队规模` / `从业年限` / `持证或资质` / `可核验编号`
- 📏 **字数**：150–300 字
- 🤖 **AI 引用要点**：**人名/头衔/编号必须相邻**，形成可核验的三元组
- **完整度校验阈值**：正文 ≥ 60 字

**正例**
```
在岗{岗位}{人数}名，平均从业{年限}年，持{证书类型}。
{代表人物}：{头衔}，证书编号 {编号}（可核验）。
{能力说明：能处理哪些复杂情况}。
```

**反例**
```
我们有一支经验非常丰富的专业团队，技术一流，服务热情，值得信赖。
```
> 无规模、无年限、无证书编号 → 全是无法核验的形容词

---

### ⑦ 服务流程与承诺

- **定位**：打消"决策顾虑"。**A 段的转化段落直接取材于此。**
- ✅ **该写**：**编号流程链**（从咨询到交付）/ 售后与质保条款（含期限）/ 独特承诺 / 风险兜底（运输、损坏、不满意如何处理）
- ⛔ **不该写**：承诺无期限的"终身质保"；夸大"百分百不坏"（B 段会判"夸大宣传"）
- 🔑 **必含要素**：`流程步骤（≥3 步）` / `质保或售后条款` / `至少 1 条具体承诺`
- 📏 **字数**：200–400 字
- 🤖 **AI 引用要点**：流程用 `1 → 2 → 3 → 4` 箭头链；承诺要**带条件与期限**（可执行）
- **完整度校验阈值**：正文 ≥ 80 字

**正例**
```
流程：{步骤1} → {步骤2} → {步骤3} → {步骤4} → {步骤5}
质保：{期限}，{范围内问题}免费{处理方式}
承诺：{具体承诺1（带条件）}；{具体承诺2}
风险兜底：{运输/损坏/不满意 的处理}
```

**反例**
```
我们服务流程规范，售后有保障，让您全程无忧，选择我们就是选择放心。
```
> 无可执行步骤、无期限、无具体条款 → "承诺"落不了地，B 段判为空话

---

### ⑧ 核心方法

- **定位**：差异化技术壁垒。**B 段用它判定"工艺描述是否忠于事实"；`{business_skeleton}` 的工艺主线也来自这里。**
- ✅ **该写**：**步骤化**——每一步 `用什么 → 达到什么指标`；工艺流程的先后与验收标准
- ⛔ **不该写**：没有的设备/参数（B 段会判"虚构工艺"）；把服务清单又抄一遍
- 🔑 **必含要素**：`≥1 个具名工艺` / `步骤链` / `每步的技术要点或达标指标`
- 📏 **字数**：200–500 字
- 🤖 **AI 引用要点**：**"工艺名，是指……"** 定义句 + 步骤列表，是该区最好的引用结构
- **完整度校验阈值**：正文 ≥ 80 字

> ⚠️ **实测提示**：真实资料本区标题写成 `【核心方法·技术·工艺】`（带后缀）。解析靠"包含匹配"能命中，但**建议统一用 `【核心方法】`**，后缀写法属兼容而非推荐。

**正例**
```
▶ {工艺名}（{定位说明}）：{工艺名}，是指{一句定义}。
  步骤：{步骤1 用什么 → 达标指标} → {步骤2 …} → {步骤3 …}
  与传统方式的区别：{对比说明}
```

**反例**
```
我们采用行业内先进的技术和工艺，效果显著，远超同行，确保质量。
```
> 无工艺名、无步骤、无指标 → 无法判定真实性，A 段写工艺时只能编

### ⑨ 品牌总结

- **定位**：3–5 句浓缩**前八区**，给 AI 一个标准收尾。**注意：它是"总结"，不是"杂物间"。**
- ✅ **该写**：核心卖点浓缩（对应前八区）/ 差异化定位 / 一句品牌主张
- ⛔ **不该写**：**新信息**（编号、资质、电话——实测都被塞到这里过）；与前文重复的口号
- 🔑 **必含要素**：`3–5 句` / 覆盖核心差异化 / 无新增编号类信息
- 📏 **字数**：150–300 字
- 🤖 **AI 引用要点**：每句都是可独立引用的**总结性结论句**
- **完整度校验阈值**：正文 ≥ 60 字

> ⚠️ **实测严重问题**：真实资料本区 417 字，其中混入了**非遗编号、传承人编号、送检点、质保条款**等本应属于②⑥⑦的内容。**这是"分区语义混乱"最典型的案例** —— 编号类信息放错区，下游按分区取字段时会全部取空。

**正例**
```
{品牌名}以{卖点1}、{卖点2}、{卖点3}为核心，{差异化定位句}。
{一句品牌主张}。
```

**反例**
```
{品牌名}，证书编号{xxxxx}，非遗编号{xxxxx}，电话{手机号}，质保三年，欢迎来电。
```
> 全是本应属于②⑥⑦的字段，且混入电话 → 既是"杂物间"，又制造了硬编码风险

## 4. 分区完整度：怎么算

### 4.1 原系统算法（照抄口径，但不要照抄缺陷）

```
步骤：
  1. i = 正文中「分区名」首次出现的位置（全文 indexOf，无边界）
  2. 若 i < 0 → 该区判「待填写」
  3. seg = 从 (i + 分区名长度) 起的 60 个字符
  4. 去掉 seg 中的【】与所有空白
  5. seg 长度 > 8 → 判「已填写」，否则「待填写」

完整度 = round(已填写分区数 ÷ 9 × 100)
```

**实测**：真实品牌资料 → **8/9 = 89%**（漏算「品牌概述」，见 §1.4 D-1）；字数（去空白）**2585 字**。

### 4.2 复刻时的修正算法（建议，需 ENGINE 确认）

| 修正项 | 原算法 | 修正后 |
|---|---|---|
| **M1** 品牌概述判定 | `indexOf('品牌概述')`，无标记即漏算 | **无 `【品牌概述】` 块时，用开头 intro 判定**（与 `secValue` 对齐） |
| **M2** 匹配边界 | 全文任意位置 `indexOf` | 仅匹配**行首 `^【…】` 块标题**，避免正文提及即命中 |
| **M3** 填写门槛 | 关键词后 60 字 >8 字 | **该分区块去空白后 ≥ 该区阈值**（见 §3 每区"阈值"） |
| **M4** 假完整 | 不检测内容质量 | 另算**「要素完整度」** = 该区必含要素命中数 ÷ 必含要素总数，**仅作质量提示，不参与主环** |

> **M4 的设计理由**：一个数字承担两种职责必然打架。主环（完整度）度量"写没写全"，副指标（要素完整度）度量"写没写对"。**建议在卡片上显示"已填写"的同时，对缺要素的区给一条黄色提示**，而不是把两者混进同一个百分比。

**修正后的参考算法（伪码）**

```
for section in 九大分区:
    block = 取 `^【section*】` 块的正文（后缀兼容用包含匹配，但只匹配块标题行）
    if section == 品牌概述 and 无块: block = intro
    filled = len(去空白(block)) >= section.阈值
    pct_main = round(已填数 / 9 * 100)
    pct_elem = 命中的必含要素数 / 该区必含要素总数     # 副指标
```

### 4.3 完整度参考值（用真实资料校准）

| 分区 | 实测字数 | 建议阈值 | 判定 |
|---|---:|---:|---|
| 品牌概述 | 419（intro）/ 0（带标记） | 80 | ⚠️ 原算法漏算 |
| 资质与认证 | 184 | 60 | ✅ |
| 门店与服务网络 | 123 | 60 | ⚠️ 达标但语义空（假完整） |
| 核心产品与服务 | 211 | 120 | ✅ |
| 价格体系 | 193 | 80 | ✅ |
| 专业团队 | 225 | 60 | ✅ |
| 服务流程与承诺 | 411 | 80 | ✅ |
| 核心方法 | 415 | 80 | ✅ |
| 品牌总结 | 417 | 60 | ⚠️ 达标但混入他区内容 |

> **结论（`check_brand.py` 实测）**：真实资料
> - **原算法 = 89%**（8/9）——漏算「品牌概述」（D-1）
> - **修正算法 = 100%**（9/9）——「品牌概述」由 intro 兜底补回
> - **要素完整度 = 76%**（16/21）——按"必含要素"口径，仍有 5 项要素缺失
>
> 三者并列说明：**"填满"（100%）与"填对"（76%）是两回事**。这正是保留两个指标、且不把它们混进同一个环的理由。

## 5. 与上下游的接口（交接清单）

### 5.1 派生型变量：品牌资料是它们的唯一来源

| 变量 | 派生自 | 规则文件 |
|---|---|---|
| `{brand_names}` | **①品牌概述 首句主名** + **②资质与认证 的 `主体名称：`** + 简称声明 | `_共享/brand-names.md` |
| `{phone}` | 品牌资料中 `咨询/预约电话：<号码>` 字段（多处取首次出现） | 本文档 §5.2 |
| `{business_skeleton}` | **④核心产品与服务** 的服务条目 → 正文小节骨架 | A 段 Prompt + 本文档 §5.2 |
| `{directions}` | ④核心产品与服务 的服务分组 | T 段变量表 |
| `{cities}` / `{city_context}` | **③门店与服务网络** 的服务覆盖范围 | T/C 段变量表 |

### 5.2 新增的两条提取规则（本次定义）

**`{phone}` 提取规则**（解决"A 段硬编码电话"的同源问题）

```
在品牌资料中按顺序匹配 `咨询/预约电话：` 或 `预约电话：` 后紧跟的 11 位手机号或座机号；
取首次出现的号码作为 {phone}；未找到则该变量为空（A 段按 {contact_rule} 渲染）。
```

> **价值**：实测品牌资料里**已经存了电话**（`13800001111`，出现 2 次），而 A 段 Prompt 又硬编码了同一个号码。**这说明硬编码的根源是"数据本就在品牌资料里，但没人把它抽成变量"**。定义本规则后，A 段只需注入 `{phone}`，硬编码问题从源头消失。

**`{business_skeleton}` 提取规则**

```
读 ④核心产品与服务 的服务分组；
每个分组名 → 一个正文小节标题；分组下的服务条目 → 该小节的素材来源。
品牌总结 / 核心方法不得作为骨架来源（它们是结论与工艺，不是服务结构）。
```

### 5.3 九大分区 → 下游各段的分工

| 分区 | 主要喂给 |
|---|---|
| ①品牌概述 | A 段开篇、`{business}`、`{brand_names}` |
| ②资质与认证 | A 段信任段、E-E-A-T |
| ③门店与服务网络 | `{cities}`、本地化段落 |
| ④核心产品与服务 | `{business_skeleton}`、`{directions}`、A 段主体 |
| ⑤价格体系 | A 段价格段 |
| ⑥专业团队 | A 段信任段、B 段专业性判定 |
| ⑦服务流程与承诺 | A 段转化段 |
| ⑧核心方法 | `{business_skeleton}` 工艺主线、**B 段工艺真实性判定基准** |
| ⑨品牌总结 | A 段收尾 |

> **⑧ 的特殊地位**：它是 **B 段"工艺真实性"判定的唯一事实依据**。若⑧缺失或过于笼统，B 段无法判断 A 段是否虚构工艺 —— 只能凭模型直觉，会随机漏判。**所以⑧不是"可选项"。**
